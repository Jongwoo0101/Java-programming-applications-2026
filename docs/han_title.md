## 1. 선거관리위원회(선관위)시스템 in 마인크래프트

마인크래프트 서버 내에서 공정한 선거를 치르기 위해 후보 등록부터 투표, 부정선거 단속, 개표까지 전 과정을 자동화하는 민주주의 시스템입니다.

* **Java 핵심 구현 포인트:**
* **객체지향 설계(OOP) 기반 데이터 구조:** 후보자(`Candidate`), 투표권자(`Voter`), 선거구(`District`) 등을 각각의 클래스로 설계합니다. 후보자 객체 내에는 기호, 이름, 공약, 득표수 등의 필드를 명시하고 이를 `HashMap<String, Candidate>` 구조로 관리합니다.
* **YAML / JSON 데이터 지속성 (Persistence):** 서버가 갑자기 꺼지더라도 투표 데이터가 날아가지 않도록, 유저가 투표할 때마다 득표 데이터와 투표 완료 유저의 UUID를 `config.yml` 파일에 실시간 혹은 주기적으로 Write(I/O) 합니다.
* **자료구조 기반 중복/부정 투표 방지:** 한 번 투표한 유저의 고유 ID(UUID)를 `HashSet`에 담아 보관합니다. 유저가 다시 투표를 시도(`InventoryClickEvent`)할 때 `contains(UUID)` 메서드로 즉시 조회하여 단 0.001초 만에 중복 투표를 차단(`event.setCancelled(true)`)합니다.
* **멀티스레드 정시 알림 및 카운트다운 (`BukkitRunnable`):** Java의 백그라운드 스레드를 이용해 선거 마감 1시간 전, 10분 전, 1분 전 등 실시간 카운트다운을 서버 전체 공지(Chat, Title API)로 띄우고, 마감 시간이 정확히 일치하면 투표 이벤트 리스너를 자동으로 비활성화(Unregister)합니다.
* **정렬(Sorting) 알고리즘을 통한 실시간 개표:** 선거가 끝나면 `List`에 담긴 후보자 객체들을 `Collections.sort()`와 `Comparator`를 활용해 득표수 기준 내림차순으로 정렬합니다. 정렬된 데이터를 기반으로 당선자를 판별하고, 서버 내 표지판(Sign)이나 홀로그램 패키지를 통해 당선자 이름과 최종 득표율을 시각화합니다.

## 2. 가상 부동산 거래 및 경매 시스템

서버 내의 특정 구역(청크 단위)을 유저들이 사고팔 수 있는 자본주의 시스템입니다.

* **Java 핵심 구현 포인트:**
* **2차원 좌표 데이터 관리:** 유저가 지정한 구역의 X, Z 좌표 범위를 객체(`Region`)로 관리하고, 파일(`YAML/JSON`)에 소유주 정보를 저장 및 로드합니다.
* **이벤트 제어:** 소유주가 아닌 다른 유저가 해당 구역의 블록을 부수거나 상자를 열려고 할 때 `BlockBreakEvent`, `PlayerInteractEvent`를 취소(`setCancelled(true)`)하여 사유지를 보호합니다.
* **실시간 경매 스레드 (`BukkitRunnable`):** 최고가 입찰이 들어오면 타이머가 갱신되고, 갱신 바가 보스바(BossBar)로 실시간 줄어드는 멀티스레딩 경매 로직을 구현합니다.

* **Java 핵심 구현 포인트:**
* **난수 기반 알고리즘 및 그래프 시각화:** 일정 시간마다 랜덤 가중치 알고리즘을 통해 주가를 변동시키고, 호재/악재 이벤트를 텍스트로 발생시킵니다. 변동된 주가는 GUI 창 안에 초록색/빨간색 양초(아이템 갯수나 종류)로 간이 차트를 그려 시각화합니다.
* **로그 및 트랜잭션 관리:** 유저별 매수/매도 시점의 자산 변화를 추적하고, 동시 구매 요청이 들어왔을 때 데이터가 꼬이지 않도록 동기화(`synchronized` 또는 순차적 큐 처리) 처리를 합니다.

단순히 AI한테 질문하고 답변받는 뻔한 챗봇이 아니라, **API의 한계나 데이터의 불규칙성 때문에 개발자가 코딩하면서 엄청나게 괴로워할 만한** 현실 밀착형 주제 3가지를 가져왔습니다.

## 14. 정형화되지 않은 데이터 지옥: 영수증/메일 인식 기반 '법인카드/동아리 총무 비용 정산 및 AI 자동 자동분류 시스템'

> **💡 한 줄 요약:** 영수증 사진을 올리거나 메일 텍스트를 긁어오면, OCR API와 AI를 거쳐 지출 내역을 가계부에 자동 입력하고 정산해 주는 웹.

* **개발자를 괴롭히는 포인트 (지옥의 난이도):**
* **비정형 데이터의 파싱:** 네이버 CLOVA OCR API 등을 쓰면 영수증 텍스트를 뽑아낼 수 있습니다. 하지만 영수증마다 가맹점명, 부가세, 합계 금액의 위치가 다 다릅니다. 이 난잡한 문자열 데이터를 자바 코드로 파싱하고 정규표현식으로 정제하는 과정이 진짜 지옥입니다.
* **AI의 불확실성(Hallucination) 제어:** AI에게 "이 영수증 보고 JSON 형식으로 식비인지, 교통비인지 분류해 줘"라고 요청했을 때, AI가 가끔 이상한 텍스트를 섞어 반환하면 자바의 JSON 파서가 터져버립니다. AI의 답변을 엄격하게 검증하는 Validation 로직을 짜야 합니다.



## 15. 동기화 및 가공 지옥: 유튜브/치지직/아프리카TV '스트리머 라이브 통합 알림 및 AI 하이라이트 요약 대시보드'

> **💡 한 줄 요약:** 내가 좋아하는 스트리머나 유튜버들을 등록해 두면, 여러 플랫폼에 흩어진 라이브 방송 시작 알림을 한곳에 모아주고, 지난 방송의 댓글/채팅창 API를 분석해 주는 웹.

* **개발자를 괴롭히는 포인트 (지옥의 난이도):**
* **서로 다른 플랫폼 API 통합:** 유튜브, 치지직, 아프리카TV의 API 명세서가 완전히 다릅니다. 어떤 곳은 Webhook을 지원하고, 어떤 곳은 계속 우리가 호출(Polling)해야 합니다. 이 상이한 아키텍처를 자바 인터페이스와 디자인 패턴(Adapter Pattern)을 활용해 깔끔하게 통합하는 설계 능력이 필요합니다.
* **대량의 텍스트 데이터 다이어트:** 방송이 끝난 후 수만 개의 실시간 채팅 데이터를 API로 긁어와서, AI에게 "오늘 방송 3줄 요약해 줘"라고 보내면 토큰 수 제한(Context Window)에 걸려 에러가 납니다. 백엔드에서 의미 없는 단어를 필터링하고 분할해서 AI에게 먹이는 '데이터 전처리 로직'을 순수 자바 코드로 짜야 합니다.

이번에는 API 비용은 완전 무료(공짜)이거나 국가/공공기관에서 제공하는 무료 키를 쓸 수 있으면서, **"데이터 구조의 복잡함"과 "실시간 동기화"로 개발자의 뚝배기를 깨버릴 수 있는 주제 3가지**를 엄선했습니다.

돈 걱정 없이, 오직 개발자의 순수 컴퓨팅 사고력과 노가다로 승부하는 지옥의 맛입니다.

## 16. 일정 분산 지옥: 네이버/구글 캘린더 API 연동 '다인원 일정 자동 빈 시간(Cross-Check) 추적 및 약속 빌더'

> **💡 한 줄 요약:** 5~6명이 팀플이나 모임을 할 때, 각자의 구글/네이버 캘린더 일정을 API로 다 긁어와서 "모두가 비어 있는 최적의 시간대"를 자바 백엔드가 계산해 주는 웹.

* **API 비용:** **완전 무료** (Google Calendar API, 네이버 개발자 API)
* **개발자를 괴롭히는 포인트 (지옥의 난이도):**
* **시간 데이터 포맷의 지옥:** 각 유저의 캘린더에서 받아온 데이터는 `UTC 타임존`, `ISO-8601` 등 형태가 제각각입니다. 게다가 '매주 반복되는 일정', '하루 종일 걸리는 일정' 등이 다 섞여 있습니다. 이 시간 데이터들을 자바의 `LocalDateTime` 객체로 정밀하게 파싱하는 것부터 머리가 깨집니다.
* **교집합 알고리즘 구현:** 유저 6명의 스케줄 배열을 겹쳐서 "모두가 비어 있는 2시간짜리 슬롯"을 찾아내야 합니다. 1차원적인 `for`문으로 짜면 서버가 멈추거나 타임아웃이 납니다. 구간 트리(Segment Tree)나 시간 배열 스캐닝 같은 알고리즘을 백엔드에 직접 구현해야 해서 개발자가 엄청나게 괴로워합니다.


오케이, 두 번 연속 까였군요! ㅋㅋㅋ 취향 저격 실패 인정합니다.

앞선 아이디어들이 너무 '취업용 교과서' 같거나 '개발자 전용 툴' 느낌이라 와닿지 않으셨을 수 있습니다.

이번엔 방향을 180도 바꿔서, **실제 돈(재테크), 대중적인 미디어(유튜브), 혹은 자극적이고 재미있는 소셜(연애/채팅)** 키워드로 가보겠습니다. 팀원들도 빌드하면서 "오, 이거 재밌는데?" 할 만한 주제들입니다.

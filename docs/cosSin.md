# 🧠 [핵심 로직 해부] 코사인 유사도는 우리 앱에서 어떻게 작동하는가?

## 📍 1. 사전 세팅 (백그라운드 데이터)

이해를 돕기 위해, 가상의 페르소나 '서연(친한 아는 누나)'과 소개팅을 한다고 가정해 보겠습니다. 시스템 내부(JSON)에는 서연이에 대한 다음과 같은 데이터가 로드되어 있습니다.

* **서연의 이상형 벡터 (Target Vector):** `[주도성 30, 순종성 10, 적극성 60]`
*(해석: 남자가 너무 주도하기보단, 적당히 리드하면서 엄청 적극적으로 애정 표현을 해주는 연하남 스타일을 선호함)*
* **서연의 호감 키워드 (`loveKeywords`):** `{"누나": 15, "아가": 15}`
* **시스템 전역 성향 키워드 (`assertiveWords`, `dominanceWords` 등):** `{"좋아해": 10, "리드할게": 10}`

## 📍 2. 유저의 입력과 텍스트 분석 (Behind the Scenes)

유저가 채팅창에 **"누나, 내가 리드할게. 진짜 좋아해."** 라고 입력하고 엔터를 치는 순간, 백엔드(`TextAnalysisEngine`)에서는 0.001초 만에 다음과 같은 두 가지 채점이 동시에 일어납니다.

### ① 호감도(Tension) 채점 (감정 상태 결정)

* 엔진은 유저의 문장을 쪼개서 `loveKeywords` 사전을 뒤집니다.
* 이때 배열을 쓰지 않고 `HashMap`을 사용했기 때문에, `"누나"`라는 단어가 있는지 처음부터 끝까지 찾는 게 아니라 **해시(Hash) 함수를 통해 $O(1)$의 속도로 즉시 15점을 꺼내옵니다.**
* **결과:** 텐션(호감도) `0점 -> 15점`으로 상승.

### ② 성향(Vector) 채점 (오늘의 핵심)

* 엔진은 동시에 3차원 성향 사전도 뒤집니다.
* `"리드할게"` 발견 -> 주도성(Dominance) 사전에서 **+10점** 획득
* `"좋아해"` 발견 -> 적극성(Assertiveness) 사전에서 **+10점** 획득
* **결과:** 유저의 성향 벡터(`userVector`)는 `[주도 10, 순종 0, 적극 10]`으로 업데이트되어 `MeltingContext`(진료 차트)에 몰래 기록됩니다.

> *이렇게 7턴 동안 대화를 진행하며, 유저의 최종 성향 벡터가 **`[주도성 10, 순종성 0, 적극성 20]`**으로 누적되었다고 가정해 보겠습니다.*

## 📍 3. 대화 종료 및 매칭 버튼 클릭! (수학적 연산의 시작)

대화가 모두 끝나고 유저가 [결과 보기]를 누르면, `MatchEngine` 객체가 깨어나 유저의 벡터와 서연의 목표 벡터를 들고 **코사인 유사도(Cosine Similarity)** 연산을 시작합니다.

### ❓ 왜 단순 덧셈/뺄셈을 안 쓰고 코사인 유사도를 쓸까요?

* 유저의 총점은 겨우 `30점(10+0+20)`이고, 서연의 목표 점수는 `100점(30+10+60)`입니다.
* 단순 점수로 빼기 연산을 하면 오차가 70점이나 나서 "당신은 서연과 30%밖에 안 맞습니다"라는 오류를 범하게 됩니다. 유저는 대화(턴) 수가 적어서 점수를 덜 모았을 뿐, 성향 자체는 서연이 원하는 스타일과 똑같은데 말이죠.
* 그래서 우리는 점수의 크기(Magnitude)가 아니라, **두 사람이 바라보는 성향의 방향(비율/각도)이 얼마나 일치하는지**를 보기 위해 삼각함수를 도입했습니다.

## 📍 4. 코사인 유사도 100% 쌩얼굴 수식 계산 (`MatchEngine.java`)

코사인 유사도 공식은 다음과 같습니다.


$$\cos(\theta) = \frac{A \cdot B}{\vert{}\vert{}A\vert{}\vert{} \vert{}\vert{}B\vert{}\vert{}}$$

자바 코드(`Math.sqrt`, `Math.pow`)가 이 공식을 어떻게 처리하는지 값을 넣어 계산해 보겠습니다.

* **A (유저 벡터):** `[10, 0, 20]`
* **B (서연 목표 벡터):** `[30, 10, 60]`

**Step 1: 내적 (A · B) 구하기**


$$(10 \times 30) + (0 \times 10) + (20 \times 60) = 300 + 0 + 1200 = 1500$$

**Step 2: 벡터 A의 크기 (||A||) 구하기**


$$\sqrt{10^2 + 0^2 + 20^2} = \sqrt{100 + 0 + 400} = \sqrt{500} \approx 22.36$$

**Step 3: 벡터 B의 크기 (||B||) 구하기**


$$\sqrt{30^2 + 10^2 + 60^2} = \sqrt{900 + 100 + 3600} = \sqrt{4600} \approx 67.82$$

**Step 4: 최종 싱크로율 계산**


$$\cos(\theta) = \frac{1500}{22.36 \times 67.82} = \frac{1500}{1516.45} \approx 0.989$$

**🔥 결과: 싱크로율 98.9% 도출!**
유저의 점수 총합은 서연이보다 한참 낮았지만, 비율을 보면 유저(1:0:2)와 서연(3:1:6)의 성향 방향성(각도)이 거의 완벽하게 일치하기 때문에 98.9%라는 놀라운 매칭 결과가 수학적으로 도출된 것입니다.

## 📍 5. 마지막 반전: 트롤링 유저 참교육 (Penalty Logic)

교수님께서 *"그럼 유저가 아무 말 대잔치나 욕설만 치고 우연히 비율이 맞으면 어떡하나요?"* 라고 날카로운 질문을 하실 수 있습니다. 이때 이 방어 로직을 설명하시면 완벽합니다.

* 만약 유저가 `"지랄", "병신"` 같은 욕설만 쳤다면?
* 유저의 성향 벡터는 아무것도 쌓이지 않아 `[0, 0, 0]`이 됩니다. 시스템은 에러를 막기 위해 이를 기본값 `[10, 10, 10]`으로 변환합니다.
* 이때 만약 서연의 이상형이 `[40, 40, 40]`처럼 밸런스형이었다면? 코사인 유사도는 각도만 보니까 "싱크로율 100%!"라는 미친 결과를 뱉어내게 됩니다.

**🛡️ `ChatSessionService`의 페널티 방어막 가동**
이를 막기 위해, 우리는 앞서 구했던 '호감도(Tension)'를 페널티 지표로 사용합니다.

```java
// 호감도가 30점 미만이면 (즉, 대화를 망치고 욕설을 했다면)
if (session.getTension() < 30) {
    // 98.9%가 나왔더라도, 강제로 0.1~0.3의 페널티 비율을 곱해버립니다.
    double penaltyRatio = (session.getTension() + 10) / 100.0; 
    syncPercent = syncPercent * penaltyRatio;
}

```


### 1. [주도, 순종, 적극] 이 3가지 기준은 모든 페르소나에게 고정인가요?

**네, 맞습니다. '평가 기준(차원)'은 고정이지만, 각자가 원하는 '점수(값)'는 모두 다릅니다.**

이걸 수학/프로그래밍적으로 설명하면 이렇습니다.

* **왜 고정해야 하는가? (벡터의 차원 일치):**
코사인 유사도(Cosine Similarity)라는 수학 공식을 계산하려면, 비교하려는 두 벡터의 **크기(차원)가 무조건 똑같아야** 합니다. 만약 어떤 페르소나는 4차원이고, 유저는 3차원이면 에러가 발생해 계산 자체가 불가능해집니다.
* **어떻게 구현되어 있나? (`PersonaRepository.java`)**
그래서 우리 시스템은 JSON 파일을 읽어올 때, 실수로 데이터가 2개만 있거나 4개가 들어와도 무조건 3칸짜리 배열(`new double[3]`)로 꽉 묶어버리도록 방어막을 쳐두었습니다.
* **페르소나별 차이점 (`personas.json`):**
항목은 `[주도, 순종, 적극]`으로 고정되어 있지만, 페르소나마다 바라는 이상형 수치(Target Vector)는 천차만별입니다.
* **서연 (츤데레):** `[55, 45, 40]` (적당한 리드와 밸런스 선호)
* **미스킴 (여왕):** `[100, 0, 70]` (극단적인 주도성과 적극성 요구, 순종은 0)

### 2. 계산된 유사도가 CUI 창(콘솔 화면)까지 전달되는 완벽한 과정

유사도 계산부터 화면 출력까지의 과정은 "계산기 -> 총괄 주방장 -> 배달용 도시락 -> 홀 서빙 직원"이라는 철저한 객체지향적 역할 분담(클린 아키텍처)을 거쳐 전달됩니다.

#### 📍 1단계: 계산기 (`MatchEngine.java`) - "순수 수학 계산"

유저가 대화 종료 후 `[1] 결과 보기`를 선택하면, 가장 먼저 `MatchEngine`이 호출됩니다.

* 여기서는 그 어떤 판단도 하지 않고, 오직 유저가 7턴 동안 모은 배열 `[10, 0, 20]`과 서연의 배열 `[55, 45, 40]`을 넣고 **코사인 유사도 수학 공식만 돌려 순수한 백분율(%) 숫자 하나만 딱 반환**합니다. (예: `98.9`)

#### 📍 2단계: 총괄 주방장 (`ChatSessionService.java`) - "로직 처리 및 포장"

점수를 넘겨받은 `ChatSessionService`의 `buildReport()` 메서드가 진짜 핵심 작업을 수행합니다.

* **페널티 적용:** 만약 텐션이 30점 밑이었다면, 방금 받은 98.9%에 강제로 페널티 비율을 곱해 10%대로 깎아버립니다.
* **최고의 짝 찾기:** 전체 19명(allPersonas)의 데이터를 쫙 돌면서, 유저와 가장 점수가 잘 맞는 다른 1명을 찾아냅니다. (예: 신유나 87.7%)
* **도시락 포장 (`MatchReport` 객체 생성):** 계산이 다 끝났다고 화면(Console)에 바로 출력(`System.out.println`)하지 않습니다. 대신 `MatchReport`라는 이름의 '데이터 전용 상자(Value Object)'에 [현재 상대 매칭률, 추천 상대 이름, 추천 상대 매칭률]을 예쁘게 담아서 반환(Return)합니다.

#### 📍 3단계: 홀 서빙 직원 (`ConsoleUI.java`) - "화면 출력"

비즈니스 로직(Service)에서 완성된 `MatchReport` 도시락 상자가 드디어 UI(ConsoleUI)로 넘어옵니다.

* `ConsoleUI` 안의 `presentResult()` 메서드가 이 상자를 받아 엽니다.
* 이곳은 "계산이 어떻게 되었는지" 전혀 모릅니다. 그저 상자 안에 있는 숫자를 꺼내서 `System.out.printf`를 이용해 화면에 예쁘게 그려주는 역할만 합니다.

```java
// ConsoleUI.java 내부의 실제 출력 코드 흐름
MatchReport report = chatSessionService.buildReport(session, persona);

System.out.printf("[결과] 당신과 %s의 페르소나 싱크로율은 %.1f%% 입니다!\n",
        persona.getName(), report.getSyncPercentWithChattedPersona());

System.out.printf("[참고] 가장 잘 맞는 상대는 %s (%.1f%%) 입니다.\n",
        report.getBetterMatch().get().getName(), report.getBetterMatchPercent());

```
